# Kubeflow Pipelines (phase 12)

**Path:** `pipelines/kubeflow/pipelines/`

## This phase composes 7–9 (and 6 / 10) — it does not reinvent them

| Concern | Where it already lives | How this package uses it |
|---------|------------------------|---------------------------|
| MIG / GPU labels | phase 7 `gpu-infra/` + ADR-003 | PyTorchJob `nodeSelector` → `vulcan.dev/gpu-pool=mig-large` |
| Multi-tenant admission | phase 8 Kueue `lq-training` + ADR-004 | PyTorchJob label `kueue.x-k8s.io/queue-name=lq-training` |
| Spot nodes + disruption | phase 9 Karpenter `vulcan-gpu-mig-large` + ADR-005 | Same node labels; spot-first training pool |
| Checkpoint on preemption | phase 9 `autoscaling/checkpointing` | PyTorchJob runs `vulcan-checkpoint-finetune` |
| Serving handoff shape | phase 6 `serving/kserve` helm | Final step emits InferenceService YAML in that format |
| eval_loss / perplexity | phase 10 SageMaker evaluate | Same formula + pin identity for cross-platform comparison |

**KFP’s job here is orchestration + handoff**, not a second scheduler or a second checkpoint library. If a reviewer is hunting for duplicated Kueue/Karpenter YAML inside this folder — they should not find it; they should find **references and labels that bind to those phases**.

## Pipeline

`vulcan_reference_tiny_llm_pipeline` (KFP SDK → compiled YAML):

1. **Train** — component body is CPU-sim for CI; cluster training is the Training Operator [PyTorchJob](../training-operator/).
2. **Evaluate** — `eval_loss` / `perplexity` aligned with `pipelines/sagemaker`.
3. **Register + handoff** — `registry.json` + `inferenceservice.yaml` (phase-6 KServe / vLLM shape).

```bash
make validate-kubeflow

```
